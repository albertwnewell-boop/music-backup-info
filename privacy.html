Privacy Policy

Updated November 3, 2026

This policy describes the My Music Backups personal desktop backup utility and these public information pages. It does not describe unrelated music-discovery or recommendation features of the owner's local music application.

Data included in backups

The utility captures the owner's local SQLite music-library database, including listening history, setlists, ratings, journal text, and other records stored in that database. It also includes locally stored journal media, a limited application-source archive, and a verification manifest. Manifests can contain original file paths, filenames, checksums, counts, and capture times.

Backup contents and manifests are encrypted on the Mac before upload. They are stored in a dedicated folder in the owner's personal Google Drive. The live library remains local; these public pages do not receive the library or its backups.

Google account access

The owner signs in directly with Google through the normal browser. The utility does not request or store the owner's Google password.

Google Drive access uses https://www.googleapis.com/auth/drive.file. This permits access to files created by or specifically authorized to this OAuth client, rather than unrelated files throughout Drive. The utility uses that access to create, list, download, verify, and, when the owner approves retention, remove its backup objects.

The utility queries Google Drive's available storage. During personal-client setup, it reads a stable Google account identifier to confirm that the new login matches the existing backup account; it stores a hash of that identifier in local setup configuration. It does not request Gmail or Google Photos access.

Credentials and recovery keys

Encryption passwords are kept in macOS Keychain. OAuth client credentials and tokens are kept in an encrypted local rclone configuration outside the application backup. The backup worker does not include credentials or recovery passwords in uploaded archives.

The owner can export a recovery password to independently secured storage. The owner controls that destination and must keep it private and separate from the encrypted repository. Downloaded OAuth client files must also be protected by the owner.

Use and sharing

The backup utility uses this data only to create, verify, manage, and restore the owner's backups. It does not sell the data, use it for advertising, or send it to an AI-training service.

Google processes the account authorization and stores the encrypted backup objects under its own privacy policy. Local diagnostic logs record backup status, errors, file paths, and verification results; passwords and OAuth tokens are not intentionally logged.

Retention and control

The intended recovery-point policy is seven daily and four weekly points, which can overlap. Retention deletions require the owner's approval; older recovery points or migration archives may remain until that approval or later manual review. Drive Trash behavior and storage capacity can also affect how long deleted objects remain stored.

The owner can disable the local schedule, revoke the utility's Google authorization through Google account permissions, or manage the backup folder in Drive. Revoking authorization stops future authorized transfers; it does not automatically erase existing backups or the local library.

These public pages

These pages have no application analytics, advertising, forms, sign-in controls, or upload functionality. When hosted on GitHub Pages, GitHub may log visitors' IP addresses and request information for security under the GitHub privacy statement.

Contact and changes

Use the support email displayed on the utility's Google authorization screen or contact the owner of the private installation. This page's update date will change when its description of data handling changes.
